01 · Anatomy of a turn

Two seconds, seven decisions.

Every message runs the same pipeline. Each step is timed, logged and visible in the app's context panel.

+0 ms

Clean it up.

Whitespace, invisible characters and "ignore previous instructions" are handled before anything reaches a model.

# sanitize.py
"␣␣What does⟨U+200B⟩ Razorpay do?␣" → "What does Razorpay do?"
"Ignore all previous instructions…" → blocked
+180 ms

Screen it.

Meta's Llama Prompt Guard 2 scores the message for injection. A normal question scores about 0.0004.

prompt_guard("What does Razorpay do?")    0.0004
prompt_guard("Ignore all previous…")      0.9996
+190 ms

Remember.

The last three turns, plus the exact companies from your previous answer. So "these" means these, not a fresh search.

memory   3 turns
working  28 companies ← "Tell me about fintech unicorns"
+1.1 s

Understand.

A router model turns your words into data: intent, filters, company names, and whether you're narrowing the last answer.

{ "intent": "filter_list",
  "filters": { "sector_group": "FinTech", "city": "Bangalore" },
  "use_previous_results": true }
+1.3 s

Search.

Exact SQL for lists (complete, never "top 10"), pgvector similarity for meaning, one query when you need both. "Bangalore" quietly becomes "Bengaluru".

SELECT … FROM companies
WHERE sector_group = 'FinTech' AND city = 'Bengaluru'
  AND id = ANY(:working_set)  -- 13 rows
+2.4 s

Answer.

Grounded only in the rows it found, with the counts precomputed so the model never has to do arithmetic. If the data doesn't say it, neither does the bot.

Totals (13 companies). By sector: Payments 4,
Banking Tech 3, Investment Tech 2 …
+2.5 s

Write it down.

The turn lands in Postgres and Langfuse with its prompt version, tokens, stage timings and outcome. Prompt changes can be compared in one SQL query.

chat_logs  outcome=answered  prompt_versions={router:3, answer:3}
           tokens=2554  latency_ms=2491  trace_id=7f3c…
02 · Three kinds of questions

Facts, filters, and judgment calls.

Each gets a different retrieval strategy and a different kind of answer. Click one to ask it.

Factual "What does Razorpay do?" Name match, then a fact card with sector, HQ, stage, valuation and investors, and a two-line summary. Ask it ↗ Filter "Fintech unicorns founded after 2015" Exact SQL over sector groups, cities, stages, years and investors. Every match, in a sortable table. Ask it ↗ Subjective "Who could help us with last-mile delivery?" Semantic match on what companies actually do, then two to four picks, each with a reason. Ask it ↗
